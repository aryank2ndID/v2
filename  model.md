Based on the `ml/train.py` script, here is a summary of how the model is trained:

### 1. Data Source (Synthetic)
The model is trained entirely on a **synthetic cohort** of simulated patients generated by `ml/simulator.py`. The script heavily emphasizes that this dataset is meant to prove the system works structurally (recovering a simulated relationship) and is **not clinical validation**. 
- It simulates data for 14,000–20,000 individuals, generating features from intake questionnaires (age, BMI, pain scores) and simulated hardware sensors (a 30-second walk and a sit-to-stand test).

### 2. Splitting Strategy
The dataset is divided using a **stratified split** to ensure balanced target labels across the splits:
- **70%** Training
- **15%** Validation (used for early stopping and picking thresholds)
- **15%** Test (held-out for honest metrics)

### 3. Algorithm & Architecture
It uses a custom **Gradient Boosting Machine (GBM)** implementation (`ml/gbm.py`) built from scratch, rather than an off-the-shelf library like XGBoost (likely to ensure the exact same inference logic can be ported to the TypeScript/on-device version).
- **Hyperparameters**: 400 trees max, max depth of 4, learning rate of 0.055, L2 regularization ($\lambda = 1.2$), and random subsampling (85% rows, 80% columns).
- **Early Stopping**: Halts training if performance on the validation set doesn't improve for 35 rounds.

### 4. Risk Banding (Threshold Selection)
Because this is a screening tool, the model sets specific cut-points to divide patients into three bands: **Low**, **Watch**, and **Refer**.
- **Refer Cutoff:** Tuned for high sensitivity ($\ge 90\%$) on the validation set. Missing a potential case is considered worse than a false alarm.
- **Low Risk Cutoff:** Tuned for a high Negative Predictive Value (NPV $\ge 97\%$), ensuring that if someone gets a "green" result, it is genuinely reassuring.

### 5. Ablation Studies
During training, the script runs an ablation study (training models with fewer features) to quantify exactly how much predictive power the hardware brings. It compares:
- Intake only (just the questionnaire)
- Intake + Gait (walking)
- Intake + Gait + STS (sit-to-stand)
- Full kit

### 6. Artifact Generation
Finally, the script exports several artifacts to `ml/out/`:
- `model.json`: The trained booster trees that get bundled into the phone/web app for on-device inference.
- `metrics.json`: Detailed performance stats, calibration data, and feature importance.
- `cohort.json`: A generated database of simulated patients used to populate the web dashboard.
- `parity.json`: Test fixtures used to prove that the TypeScript inference engine gives the exact same results as the Python training script.
